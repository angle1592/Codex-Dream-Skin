# Windows 主题级任务页背景强度设计

日期：2026-07-19
状态：已完成交互方案确认，等待书面规格审阅
目标分支：`agent/windows-theme-strength-control`

## 1. 背景与目标

Codex Dream Skin 目前可以为 Codex 和 ChatGPT 窗口设置背景图，但 Codex 任务/对话页面的遮罩强度是写死的。不同图片的亮度、主体位置和细节密度不同，同一组遮罩值无法同时兼顾图片可见度与文字可读性。

本功能为每个主题增加独立的“Codex 任务/对话页面的背景强度”设置。用户可以从托盘菜单打开滑块并实时预览；确认后，该值随主题保存，切换回来时自动恢复。

## 2. 范围

### 2.1 包含

- Windows 托盘菜单新增“任务页背景强度…”入口。
- 使用 0–100 的滑块调整当前主题的任务页背景强度。
- 滑动时约 200 毫秒防抖并实时预览。
- 每个已保存主题独立保存该值。
- 未保存的当前主题也可以调整，并在以后执行“保存当前主题”时继承该值。
- 兼容缺少新字段的旧主题。
- 更新中英文使用说明和 Windows 管理说明。

### 2.2 不包含

- 不调整 Codex 首页或 ChatGPT 首页的背景效果。
- 不调整输入框、按钮、文字、主题色、图片焦点或任务页布局。
- 不添加全局统一强度设置。
- 不把 Wallpaper Engine、初音或其他第三方图片提交到仓库。
- 不向上游仓库创建 PR；完成后发布到用户自己的 GitHub 仓库。

## 3. 用户体验

托盘右键菜单新增：

```text
任务页背景强度…
```

点击后打开模态 WinForms 对话框，包含：

- 说明文字“Codex 任务/对话页面的背景强度”；
- 0–100 的 `TrackBar`；
- 当前百分比；
- “确定”和“取消”按钮。

交互规则：

1. 打开时读取当前活动主题的有效值；缺少或无效时显示默认值 55。
2. 滑动后约 200 毫秒写入预览值并触发重新应用；连续拖动只应用最后一次稳定值。
3. 点击“确定”保存当前值。
4. 点击“取消”、按 Esc 或关闭窗口，恢复打开对话框时该字段的原始状态，包括原本不存在的情况。
5. 如果皮肤当前未运行，仍允许修改和保存，但明确提示“实时预览不可用，将在下次应用主题时生效”。
6. 如果对话框打开期间活动主题被其他操作切换，预览、确定和回滚均不得覆盖新主题；对话框停止写入并提示用户重新打开设置。

数值语义：

- 0：任务页看不到背景图，保持可读的纯界面效果；
- 55：与当前已验证的默认效果一致；
- 100：背景图最清晰，但侧边栏和文字区域仍保留最低限度的可读性遮罩。

## 4. 主题数据模型

在 `theme.json` 的 `art` 对象内增加：

```json
{
  "art": {
    "taskBackgroundStrength": 55
  }
}
```

规则：

- 持久化类型为 JSON 整数，合法范围为 0–100（含边界）；数字字符串不视为合法值。
- 字段缺失、不是有限 JSON 数字、不是整数或超出范围时，读取结果回退为 55。
- UI 写入值来自整数刻度，并在写入边界再次限制到 0–100；程序内部若收到小数，使用 `floor(value + 0.5)` 取最近整数，避免 PowerShell 与 JavaScript 的中点取整差异。
- 不为了兼容读取而自动改写旧主题；只有用户确认设置或其他正常主题写入操作发生时才持久化新字段。
- 现有主题 ID 是同步活动主题与已保存主题的唯一依据；不通过显示名称匹配。

## 5. 强度到遮罩的映射

背景强度控制任务页专用的四个遮罩百分比，不修改首页使用的 `--dream-immersive-*` 变量。

新增或动态覆盖以下任务页变量：

- `--dream-task-immersive-sidebar`
- `--dream-task-immersive-edge`
- `--dream-task-immersive-mid`
- `--dream-task-immersive-far`

使用分段线性插值，三个锚点如下：

| 强度 | sidebar | edge | mid | far |
|---:|---:|---:|---:|---:|
| 0 | 100% | 100% | 100% | 100% |
| 55 | 56% | 56% | 44% | 32% |
| 100 | 25% | 20% | 10% | 0% |

计算规则：

- `0 <= strength <= 55`：在强度 0 与 55 的两组锚点之间线性插值；
- `55 < strength <= 100`：在强度 55 与 100 的两组锚点之间线性插值；
- 输出保留至多两位小数，并作为 `color-mix()` 的百分比使用。

这样可以保证 55 完全保持当前效果、0 完全遮住任务页背景、100 尽可能显示图片，同时在侧边栏和主要文字起始区域保留保护层。

## 6. 组件与职责

### 6.1 `windows/scripts/theme-windows.ps1`

新增可复用的主题强度读写函数，负责：

- 校验并规范化 `art.taskBackgroundStrength`；
- 获取活动主题的 ID、路径和值；
- 原子写入活动主题的 `theme.json`；
- 在用户确认时，按主题 ID 将相同值同步到对应的已保存主题；
- 保持现有路径边界、重解析点防护和 UTF-8 写入约束。

预览阶段只改活动主题，不改已保存主题。确认阶段才同步已保存主题。

### 6.2 `windows/scripts/task-strength-dialog.ps1`

新增独立脚本，负责：

- 创建 WinForms 对话框与 `TrackBar`；
- 保存打开时的主题 ID、主题文件状态和原始字段状态；
- 用约 200 毫秒定时器合并连续滑动预览；
- 调用主题读写函数与现有重新应用流程；
- 处理确定、取消、关闭、皮肤未运行和主题并发切换。

该脚本只编排界面与生命周期，不复制主题文件安全逻辑。

### 6.3 `windows/scripts/tray-dream-skin.ps1`

只增加菜单项、状态控制和对话框启动调用。托盘脚本不直接编辑 JSON，也不包含强度映射算法。

### 6.4 `windows/assets/renderer-inject.js`

负责：

- 将新字段规范化为 0–100，默认 55；
- 按第 5 节的锚点计算四个任务页遮罩值；
- 设置任务页专用 CSS 变量；
- 清理或重装注入时正确替换变量，不残留前一个主题的值。

### 6.5 `windows/assets/dream-skin.css`

继续由任务页选择器消费四个任务页变量。首页选择器仍消费原有 `--dream-immersive-*` 值，确保首页外观不随滑块变化。

## 7. 写入、预览与并发安全

### 7.1 原子写入

所有 `theme.json` 更新继续使用临时文件加原子替换的现有写入方式。不得直接截断目标 JSON，也不得触碰主题图片。

### 7.2 对话框会话标识

打开对话框时记录：

- 活动主题 ID；
- 活动主题 JSON 中该字段的原始状态，包括字段不存在、原始值无效或原始值有效三种情况；
- 用于检测外部修改的文件状态标识（至少包含最后写入时间与内容哈希中的一种可靠标识）。

每次预览和确认前重新读取活动主题。如果 ID 不同，视为主题已切换并停止写入。

### 7.3 取消与关闭

取消时仅在以下条件都满足时恢复原始字段状态：

- 当前仍是打开对话框时的主题 ID；
- 当前文件状态可归因于本对话框最后一次预览写入；
- 没有检测到无法合并的外部修改。

若任一条件不满足，则不回滚文件，并提示“主题已在其他位置更改，未覆盖新的设置”。

恢复只修改 `art.taskBackgroundStrength`：原本不存在就删除预览新增的字段，原本无效或有效则恢复原始 JSON 值。不得用打开时的整份主题 JSON 覆盖其他字段。


### 7.4 确定

确定时：

1. 校验当前活动主题仍为原主题；
2. 原子写入最终值到活动主题；
3. 若存在相同 ID 的已保存主题，原子同步其 JSON；
4. 保持活动主题为已应用状态；
5. 关闭对话框。

如果当前主题尚未保存，不自动新建主题；其设置留在活动主题中，并由以后“保存当前主题”操作复制。

## 8. 错误处理

- JSON 无法解析、路径越界、原子写入失败或重新应用失败时，显示可执行的中文错误信息并保留日志路径。
- 预览失败时不自动提交已保存主题。
- 最终应用失败时不宣称设置已生效；已安全写入的主题值可以保留，提示用户稍后重新应用。
- 托盘进程不得因对话框异常退出；异常由对话框脚本返回并由托盘显示。
- PowerShell 5.1 下所有中文脚本保持兼容编码。

## 9. 测试与验收

### 9.1 自动化测试

在 Windows 测试套件中覆盖：

- 字段缺失、数字字符串、小数、非有限数字和越界值均回退为 55；
- 0、55、100 和普通中间值的映射结果；
- 预览只改活动主题，确定后才同步相同 ID 的已保存主题；
- 两个已保存主题各自保留不同强度，来回切换后恢复正确值；
- 未保存主题的值在“保存当前主题”后被复制；
- 取消、Esc 和关闭窗口恢复原值；
- 对话框期间切换主题或外部改写 JSON 时不覆盖新值；
- 皮肤未运行时可以保存且不会错误报告实时预览成功；
- 主题 JSON 写入仍为原子操作，图片哈希不变；
- PowerShell 5.1 语法和中文文本兼容；
- `renderer-inject.js` 通过 `node --check`；
- 完整 `windows/tests/run-tests.ps1` 回归测试通过。

### 9.2 页面级验收

通过现有 CDP/浏览器验证：

- 在 Codex 任务/对话路由，0、55、100 的计算样式按预期变化；
- 在 Codex 首页和 ChatGPT 首页，调整该值前后的相关计算样式保持不变；
- 切换主题后，任务页立即采用该主题自己的强度；
- 正常启动 Codex 与通过 Dream Skin 启动的既有行为不退化。

### 9.3 人工验收

- 托盘菜单名称清晰，滑块百分比与实际值同步；
- 拖动连续、预览无明显重复弹窗或进程堆积；
- 0 时任务页背景不可见；
- 55 与当前效果一致；
- 100 时图片明显更清晰且主要文字仍可读；
- “确定”在重启和主题切换后仍保留；
- “取消”不留下预览值。
